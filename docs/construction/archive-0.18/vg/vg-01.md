# Báo cáo kiểm chứng VG-01 — Ghi file trên Windows NTFS

- **Bài kiểm chứng:** VG-01 (SPEC-01.1 mục 12, SPEC-07 mục 5.1)
- **Kiểm chứng cho:** ADR-BE-18 (Ghi file, transaction, export manifest)
- **Gói công việc:** WP-0.08 (Spike Backend)
- **Ngày thực hiện:** 2026-10-11
- **Môi trường đo đạc:** Windows 11 Pro, Node 22.19.0, NTFS, ổ đĩa SSD
- **Thư viện kiểm chứng:** `write-file-atomic@7.0.1` (giấy phép ISC)
- **Kết luận:** **ĐẠT (PASSED)**

---

## 1. Mục tiêu và Tiêu chí đạt

### 1.1. Mục tiêu

Kiểm chứng tính an toàn của thư viện `write-file-atomic` kết hợp cơ chế retry luỹ tiến (ADR-BE-18) trên hệ thống tệp Windows NTFS nhằm loại trừ hoàn toàn các lỗi tranh chấp khóa file (`EPERM`, `EBUSY`, `EACCES`) thường gặp do Windows Defender, Search Indexer hoặc VS Code gây ra. Đồng thời kiểm chứng cơ chế Transaction & Rollback khi xuất hàng loạt file.

### 1.2. Tiêu chí đạt theo SPEC-01.1 mục 12

1. Ghi 100 lần liên tiếp vào file đích: 100/100 lần thành công, không file rỗng hay ghi dở, không còn file tạm (`.tmp*`).
2. Tranh chấp khóa file: Cơ chế retry luỹ tiến tự động hồi phục khi file đang bị handle khác chiếm dụng tạm thời.
3. Transaction lỗi: Mô phỏng xuất 20 file với lỗi kích hoạt ở file thứ 15 — 14 file trước được khôi phục đúng nội dung cũ từng byte, các file mới tạo bị xóa sạch.

## 3. Phân tích kỹ thuật và Khuyến nghị triển khai

### 3.1. Phiên bản thư viện `write-file-atomic`

- Phiên bản mới nhất `8.0.0` yêu cầu Node.js `^22.22.2 || ^24.15.0 || >=26.0.0`. Khi cài đặt trên môi trường hiện tại (Node 22.19.0), `pnpm` kích hoạt kiểm tra nghiêm ngặt `engineStrict` và báo lỗi không tương thích.
- Phiên bản `7.0.1` yêu cầu Node.js `^20.17.0 || >=22.9.0`, hoàn toàn tương thích và hoạt động ổn định trên cả Node 22 LTS lẫn Node 24.
- **Khuyến nghị:** Ghim phiên bản `write-file-atomic@7.0.1` theo đúng quy định tại SPEC-01.1 mục 13.3.

### 3.2. Chiến lược Rollback của Export Transaction

- Trong kịch bản S6 (file đích bị Read-Only hoặc lỗi quyền truy cập), nếu động cơ rollback cố gắng ghi đè lại chính file đang bị lỗi quyền truy cập đó, quá trình rollback sẽ bị lỗi thứ cấp.
- **Bài học kiến trúc:** Động cơ Transaction chỉ thực hiện rollback đối với:
  1. Danh sách các file thực sự đã bị thay đổi nội dung trên đĩa trước thời điểm lỗi (`actuallyModifiedOnDisk` khôi phục từ snapshot).
  2. Danh sách các file mới thực sự đã được tạo trên đĩa trước thời điểm lỗi (`newlyCreatedOnDisk` gọi `unlink`).
     Các file chưa bị tác động hoặc bị lỗi ngay từ bước ghi đầu tiên không cần và không được ghi lại trong pha rollback.

Kịch bản và báo cáo này là căn cứ để nghiệm thu gói **WP-0.08** và cổng **G0**.
